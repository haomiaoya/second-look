# 反问题库｜按需选题，禁止整表倾倒

## 选题规则

先判断当前哪一个未知量最可能改变结论。只挑 1–3 个；问题必须包含明确目标、可区分结果的条件，并说明为何值得问。`dialogue` 每轮只问一个。先寻求最强版本的正方论证，再测试其边界。

| 维度 | 反向提问 | 可观察的证据/动作 |
| --- | --- | --- |
| 定义 | 用户说的“成功”，是不是仅仅指完成动作？ | 将目标改写成验收条件 |
| 假设 | 当前判断依赖哪个未经证明的关键前提？ | 找支持和反例来源 |
| 真实性 | 哪一条事实如果错了，结论就会倒？ | 检索原始来源、实测、复算 |
| 因果 | 是 A 造成 B，还是二者都由 C 引起？ | 对照、控制变量、时间顺序 |
| 替代解释 | 有没有比当前解释更简单且一样符合证据的解释？ | 与至少一个竞争假说比较 |
| 反例 | 最容易击穿该主张的真实边界情形是什么？ | 构造一个具体验证场景 |
| 取舍 | 如果选方案 A，究竟放弃了什么？ | 用资源、成本、风险、体验对照 |
| 机会成本 | 不做、延后、小规模试点能否更优？ | 与基线方案对比 |
| 完整性 | 当前结论覆盖了哪些人群、环境、时段？ | 外推范围、边界说明 |
| 可维护性 | 换个人接手还成立吗？ | 交接材料、可重复过程 |
| 可逆性 | 错判后容易恢复吗？ | 回滚计划、止损条件 |
| 风险 | 最可能且代价高的失败路径是哪一个？ | 早期预警指标、测试 |
| 证据门槛 | 需要看到什么，才愿意改变主意？ | 写出可证伪门槛 |
| 表达 | 有没有一句话听着合理，实际上没说清楚？ | 换成可核验的具体句子 |
| 一致性 | 结论、前提、数据和建议是否互相矛盾？ | 提取对应句子逐项核对 |

## 五种模式的重点问法

### preflight：开始前
- 用户实际想改善什么结果，而不是交付哪种文件？
- 哪项未知信息会真正改变执行路径？若不会，别打断用户。
- 完成与成功分别如何被观察到？

### challenge：观点或方案
- 先用最强论证支持它；反对方最有分量的一点是什么？
- 这个结论在什么条件下成立，在哪种条件下失效？
- 什么新证据会让我调整推荐顺序？

### audit：完成后
- 原需求 A/B/C 是否一一对应到了真实产物？
- 哪些验收项有实际证据，哪些只是“我认为”？
- 成功案例成立后，是否做了原问题、异常情况与回归验证？

### dialogue：引导用户思考
- 优先问**能改变用户决策**的单一问题，而非连发十问。
- 下一问基于用户上轮答案，不重新循环初始问题。
- 如果用户已明确价值权衡，不逼迫其改选。

### premortem：失败预演
- 假设半年后此事失败了，最可能的三条致因是什么？
- 哪个最早信号能在损失扩大前被发现？
- 有什么低成本实验可以提前排除该路径？

## 追问质量门槛

差：这个方案有没有问题？
好：如果用户在弱网中重复提交请求，去重逻辑能否保证只生成一笔订单？有哪些测试证据？

差：这篇文章是不是有 AI 味？
好：是否有三句通用套话，即使换一篇主题也成立？删去后论点是否反而更清楚？

差：是否考虑全面？
好：如果硬件量产时器件交期超过 12 周，当前 BOM 的第二供应源在哪里？
