# 场景专项核查｜只读当前任务相关的一节

注意：检查工具实际可用才运行；没有可用验证工具，就报告“未验证”，不得模拟成功。

## 1. 代码 / 软件 / 嵌入式

- 原问题或故障能否复现？现在用同一条件是否消失？
- 需求和接口是否匹配？构建、静态检查、自动化测试是否真实运行？
- 关键异常：超时、掉电、重连、竞争、边界、容量、资源释放、安全、回滚。
- 嵌入式补充：ISR/RTOS 优先级和 API 限制、DMA/缓存一致性、看门狗、任务栈、长期运行、硬件实测条件。
- “编译通过”只能证明编译，不证明硬件现象或业务目标达成。

## 2. 文档 / 报告 / 需求说明

- 是否准确覆盖用户最初指定的受众、篇幅、结构、术语和硬约束？
- 每个重要结论是否有来源、数据、推导或清晰标注的主观判断？
- 图、表、章节、引用、附件是否和正文一致？是否有重复、逻辑跳跃、张冠李戴？
- 交付的文件是否实际生成、能打开且是用户要求的格式？未实际检查不得声称正常。
- 风格审查针对目标文风，而非默认“公文体”；“读起来顺”不等于“事实对”。

## 3. 产品 / 系统 / 硬件方案

- 用户场景是否真实？哪个需求必须做，哪个只是有趣？
- 关键假设：价格、供应链、成本、功耗、物理约束、可靠性、标准和量产制造。
- 选型是否对比过替代路线？哪些依赖需要样机实测才能确认？
- 失败预演：单点器件停产、指标实测不达标、数据链断、可维修性不足。

## 4. 调研 / 知识问答 / 事实核查

- 先核定义与时间范围；确认一手来源或多源独立性。
- 事实、行业观点和个人建议分开；引文不能支持超出其范围的结论。
- 证据缺席不是“证伪”；搜不到不等于没有。
- 对迅速变化的信息标明核查日期和不足。

## 5. 商业 / 求职 / 个人决策

- 决策目标是谁的、如何衡量成功，是否存在多目标冲突？
- 对比“不做”“延后”“小规模试行”，不要只有 A/B 二选一。
- 反方最强理由是什么？最坏合理损失、退出条件、可逆性如何？
- 偏好不能由 AI 代替选择；应把关键权衡展示给用户。

## 6. 写作 / 内容 / 创意

- 是否抓住**原本想表达的东西**，而不是把用户的文字改成 AI 的标准论述？
- 结构是否服务阅读体验，论点和例子之间有没有实际联系？
- 删掉任何主题都通用的套话后，内容损失了什么？
- 有无伪造经历、引用、数据或不必要的过度润色？
- 客观错误要指出；审美主张应作“可能更符合目标”的条件性意见。

## 7. 医疗 / 法律 / 财务 / 安全（高风险）

- 先辨明信息时效与适用对象，事实来源、推断、风险和专业建议分别标明。
- 缺失的重要数据或关键禁忌能否改变行动？若能，应提示专业核实。
- 不仅问“有无好处”，更问“如果判断错误会导致什么损害”？
- 不假装完成了临床、法律或工程合规鉴定，严禁编造检测结论。
